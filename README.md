# 가족여행 플래너

2026년 10월 26일~30일 가족 여행. 기존 1~5일차 일정과 개인 저장을 유지합니다.

## 여행 정보와 일차 관리

- 상단 연필 또는 부가내용을 눌러 제목과 여러 줄 설명을 편집합니다. 기존 제목과 설명은 이전 데이터의 표시 기본값으로만 사용하며 서버 데이터를 초기화하지 않습니다.
- `일차 관리`에서 일차를 추가하고, 탭 이름·날짜·설명을 편집하거나 화살표로 순서를 바꿀 수 있습니다. 날짜는 탭 이름에 자유롭게 입력합니다.
- 일차 삭제는 포함된 일정 수를 확인한 뒤 적용합니다. 일차는 0~60개이며, 0개여도 준비물·구매 목록은 유지합니다. 이름은 자유 형식으로 유지하며 순서 이동 시 자동 변경하지 않습니다.
- 제목/설명/일차 변경도 기존 version 조건부 저장 및 충돌 선택을 사용합니다. 일차 삭제와 다른 사용자의 내부 일정 수정이 겹치면 선택이 필요합니다.
- 이전 앱의 저장에서 새 제목·설명이 누락되더라도 서버가 보존합니다. 기존 로컬 저장 키와 초대 링크는 유지하며 삭제한 기본 일차를 다시 추가하지 않습니다.

## 가족 공동 편집

첫 탭 ‘준비물’에서 그룹별 물건과 챙김 체크를 관리합니다. 기본 예시는 아윤이짐(잠옷·장난감), 공통(칫솔 3개)입니다. 그룹과 항목의 추가·수정·삭제를 지원하며, 준비물 챙김 수는 여행 일정 진척도와 별도로 표시합니다. 공유 시 준비물도 같은 충돌 방지·오프라인 저장을 사용합니다. 예전 앱에서 일정을 저장해도 서버가 준비물 정보를 보존합니다.

동기화 버튼은 상단 오른쪽에 있고, 가족 공유 설정은 기본적으로 접혀 있습니다.

- 개인에게 전달된 가족용 링크로 연결한 뒤 ‘가족에게 공유’에서 링크를 복사하거나 공유합니다.
- 링크를 가진 사람은 같은 일정의 추가·수정·삭제·완료 체크가 가능합니다. 초대 키는 소스에 포함하지 않습니다.
- 화면이 열려 있으면 약 30초마다 변경을 확인하고, 다시 접속하거나 온라인으로 돌아오면 동기화합니다. 수정은 즉시 저장하며 편집 창이나 일차 관리 창을 연 동안 정기 조회를 잠시 멈춥니다.
- 연결이 끊기면 브라우저에 수정 초안을 보관합니다. 저장 완료 전에는 브라우저 데이터를 지우지 마세요.
- 서로 다른 항목/필드의 수정은 3-way merge로 합칩니다. 같은 필드, 수정/삭제 충돌은 사용자가 선택합니다.
- 저장 API의 version 조건부 갱신으로 마지막 저장이 앞선 수정을 덮어쓰는 것을 방지합니다.
- ‘이 기기의 이전 수정 가져오기’로 기존 개인 수정과 공동 일정을 합칠 수 있습니다. 원본 개인 저장은 보존합니다.

## 운영

GitHub Pages는 main 브랜치의 루트에서 배포합니다. Safari → 공유 → 홈 화면에 추가하면 앱처럼 사용할 수 있습니다.

Supabase `family-trip` Edge Function은 256비트 초대 키의 SHA-256 해시를 확인한 뒤 서버에서만 데이터에 접근합니다. 테이블은 RLS가 켜져 있으며 공개 클라이언트 접근 정책이 없는 것이 의도된 설정입니다. 서비스 키는 서버 환경 변수에서만 사용합니다.

서버 소스: `backend/family-trip.js`. 프런트엔드 연결 주소: `app.js`. 공유키와 실제 공유 일정은 저장소에 넣지 않습니다. `access_hash`의 기존 초대 링크는 보존하고, 승인된 추가 링크는 `additional_access_hash`로 연결할 수 있습니다. 새 링크 권한 부여는 소유자 확인 후 진행합니다.

검증: `node --test tests/*.test.cjs`. 브라우저 검증은 `node tests/browser.cjs`로 로컬 서버와 격리된 API를 사용합니다. 실제 가족 데이터에는 테스트 수정 내용을 저장하지 않습니다.

3~5일차는 추천 일정이며 귀가 항공편 시각은 미정입니다.

## 가족 웹 푸시 알림

- 시작 시간이 있는 일정은 기본적으로 시작 10분 전 알림 대상입니다. 일정 수정의 `10분 전 미리 알림`을 끄면 가족 모두에게 적용됩니다. `reminder` 누락은 켜짐으로 해석합니다.
- 일차 수정의 `실제 날짜`와 시작 시간을 한국 시간(Asia/Seoul, UTC+09:00)으로 계산합니다. 날짜나 시간이 없으면 발송하지 않습니다. 탭 이름 변경은 실제 날짜 변경과 별개입니다.
- `가족 일정 알림`에서 기기 이름과 별도 가족 등록 코드를 입력하고 권한을 허용합니다. 승인된 활성 기기는 최대 2대입니다. 가족 링크만으로는 새 기기를 등록하거나 다른 기기를 해제할 수 없습니다. 각 기기의 수신 해제는 자기 기기만 대상으로 합니다.
- 아이폰은 홈 화면에 추가한 웹 앱에서 등록해야 합니다. 새로 설치하거나 브라우저 데이터를 삭제하면 재등록이 필요할 수 있습니다. 기기 관리에서 이전 기기를 해제할 수 있습니다.
- 서버 cron이 매분 최신 일정을 확인합니다. 실제 호출은 활성 수신 기기와 발송 시각에 도달한 일정이 있을 때만 발생합니다. 10분 미만 남은 새 일정도 다음 확인 때 발송하고, 이미 시작된 일정은 발송하지 않습니다. 매분 확인으로 약 1분의 오차 및 푸시 서비스·단말의 지연이 있을 수 있습니다.
- 날짜·시간 변경은 새 시각으로 계산하고, 삭제·알림 끄기는 최신 데이터 재확인에서 제외합니다. 이미 푸시 서비스에 전달된 알림은 취소할 수 없습니다. 완료 체크와 알림 끄기는 별개입니다.
- 기기/일정/시작 시각별 발송 이력과 원자적 선점으로 중복 실행을 막습니다. 실패는 최대 3회, 시작 시각 전까지만 재시도합니다. 응답 유실 시 재시도 중복 가능성은 같은 notification tag로 완화합니다. TTL도 일정 시작까지로 제한합니다. 만료된 수신 정보(404/410)는 비활성화합니다.
- `family-push`는 가족 키 + 등록 코드/기기 토큰 또는 별도 scheduler secret으로 인증하므로 플랫폼 JWT 검증은 끕니다. 수신 URL은 Apple/Google/Mozilla HTTPS 호스트만 허용하며 리다이렉트를 금지합니다.
- Push config, devices, deliveries는 RLS를 켜고 anon/authenticated/public 권한을 모두 회수합니다. 서비스 역할만 접근하며 RPC도 서비스 역할만 실행합니다. VAPID 비밀키·등록 코드·스케줄러 비밀키는 저장소에 넣지 않습니다. 정책이 없는 RLS 테이블은 공개 접근 차단을 의도한 구성입니다.
- `backend/push-schema.sql`은 DB 구조, `backend/enable-push-schedule.sql`은 최초 날짜 연결과 cron 설정, `backend/family-push.js`는 발송/기기 API입니다. config 값은 별도로 안전하게 생성해 주입합니다. 스키마 SQL은 배포 이력의 재현용이며 정상 운영 중 다시 적용할 필요가 없습니다.
- 검증: `node --test tests/*.test.cjs`; DOM UI 검증은 jsdom 26.1.0이 설치된 환경에서 `node tests/push-ui.cjs`. 기존 Playwright 시나리오는 `node tests/browser.cjs`입니다. 실제 휴대폰 잠금화면 수신은 각 기기 등록 후 확인해야 합니다.


## 사야 할 것 · 준비물 변경 알림

- 서버에 저장된 `shopping` 또는 `packing` 내용이 바뀌면, 변경 시점에 등록된 활성 가족 기기 모두에게 알립니다. 수정한 본인도 포함합니다. 항목·그룹 추가/수정/삭제와 체크 변경을 포함하며 조회, 동일 내용 재저장, 일정·메모 수정만으로는 목록 알림을 만들지 않습니다.
- 문구는 `사야할것에 변경사항이 있습니다`, `준비물에 변경사항이 있습니다`입니다. 알림을 누르면 해당 탭으로 이동하고 최신 데이터를 조회합니다.
- DB 트리거가 저장 트랜잭션 안에서 기기별 발송 대기 행을 생성하고, 커밋 후 비동기로 발송 함수를 호출합니다. 실패 시 기존 매분 cron이 재시도합니다. 최대 3회 시도, 1시간 유효기간이며 비활성 기기는 발송 직전 다시 제외합니다.
- 원자적 선점과 버전/기기/목록별 고유 키로 중복 작업을 제한합니다. 응답 유실 시의 재전송은 동일 알림 tag를 사용합니다. 새로 등록한 기기에는 등록 전 변경 이력을 보내지 않습니다.
- 배포 순서: `backend/list-change-notifications.sql` → 새 `family-push` 함수 → `backend/activate-list-changes.sql`. 실제 일정/준비물 데이터나 등록 기기를 변경하지 않습니다.
- `tests/list-change-db.sql`은 별도 테스트 여행을 생성한 뒤 전체 트랜잭션을 rollback합니다. 실제 가족에게 테스트 알림을 보내지 않습니다.
- Safari 시간 입력칸은 `minmax(0,1fr)` 그리드, 필드의 `min-width:0`, native appearance 제거로 입력칸 겹침과 오른쪽 넘침을 방지합니다.
