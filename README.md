# 가족여행 플래너

2026년 10월 26일~30일 가족 여행. 기존 1~5일차 일정과 개인 저장을 유지합니다.

## 여행 정보와 일차 관리

- 상단 연필 또는 부가내용을 눌러 제목과 여러 줄 설명을 편집합니다. 기존 제목과 설명은 이전 데이터의 표시 기본값으로만 사용하며 서버 데이터를 초기화하지 않습니다.
- `일차 관리`에서 일차를 추가하고, 탭 이름·날짜·설명을 편집하거나 화살표로 순서를 바꿀 수 있습니다. 날짜는 탭 이름에 자유롭게 입력합니다.
- 일차 삭제는 포함된 일정 수를 확인한 뒤 적용합니다. 일차는 0~60개이며, 0개여도 준비물·구매 목록은 유지합니다. 이름은 자유 형식으로 유지하며 순서 이동 시 자동 변경하지 않습니다.
- 제목/설명/일차 변경도 기존 version 조건부 저장 및 충돌 선택을 사용합니다. 일차 삭제와 다른 사용자의 내부 일정 수정이 겹치면 선택이 필요합니다.
- 이전 앱의 저장에서 새 제목·설명이 누락되더라도 서버가 보존합니다. 기존 로컬 저장 키와 초대 링크는 유지하며 삭제한 기본 일차를 다시 추가하지 않습니다.

## 가족 공동 편집

첫 탭 ‘준비물’에서 그룹별 물건과 챙김 체크를 관리합니다. 기본 예시는 아윤이짐(잠옷·장난감), 공통(칫솔 3개)입니다. 그룹과 항목의 추가·수정·삭제를 지원하며, 준비물 챙김 수는 여행 일정 진척도와 별도로 표시합니다. 공유 시 준비물도 같은 충돌 방지·오프라인 저장을 사용합니다. 예전 앱에서 일정을 저장해도 서버가 준비물 정보를 보존합니다.

동기화 버튼은 상단 오른쪽에 있고, 가족 공유 설정은 기본적으로 접혀 있습니다.

- 개인에게 전달된 가족용 링크로 연결한 뒤 ‘가족에게 공유’에서 링크를 복사하거나 공유합니다.
- 링크를 가진 사람은 같은 일정의 추가·수정·삭제·완료 체크가 가능합니다. 초대 키는 소스에 포함하지 않습니다.
- 화면이 열려 있으면 약 30초마다 변경을 확인하고, 다시 접속하거나 온라인으로 돌아오면 동기화합니다. 수정은 즉시 저장하며 편집 창이나 일차 관리 창을 연 동안 정기 조회를 잠시 멈춥니다.
- 연결이 끊기면 브라우저에 수정 초안을 보관합니다. 저장 완료 전에는 브라우저 데이터를 지우지 마세요.
- 서로 다른 항목/필드의 수정은 3-way merge로 합칩니다. 같은 필드, 수정/삭제 충돌은 사용자가 선택합니다.
- 저장 API의 version 조건부 갱신으로 마지막 저장이 앞선 수정을 덮어쓰는 것을 방지합니다.
- ‘이 기기의 이전 수정 가져오기’로 기존 개인 수정과 공동 일정을 합칠 수 있습니다. 원본 개인 저장은 보존합니다.

## 운영

GitHub Pages는 main 브랜치의 루트에서 배포합니다. Safari → 공유 → 홈 화면에 추가하면 앱처럼 사용할 수 있습니다.

Supabase `family-trip` Edge Function은 256비트 초대 키의 SHA-256 해시를 확인한 뒤 서버에서만 데이터에 접근합니다. 테이블은 RLS가 켜져 있으며 공개 클라이언트 접근 정책이 없는 것이 의도된 설정입니다. 서비스 키는 서버 환경 변수에서만 사용합니다.

서버 소스: `backend/family-trip.js`. 프런트엔드 연결 주소: `app.js`. 공유키와 실제 공유 일정은 저장소에 넣지 않습니다. `access_hash`의 기존 초대 링크는 보존하고, 승인된 추가 링크는 `additional_access_hash`로 연결할 수 있습니다. 새 링크 권한 부여는 소유자 확인 후 진행합니다.

검증: `node --test tests/*.test.cjs`. 브라우저 검증은 `node tests/browser.cjs`로 로컬 서버와 격리된 API를 사용합니다. 실제 가족 데이터에는 테스트 수정 내용을 저장하지 않습니다.

3~5일차는 추천 일정이며 귀가 항공편 시각은 미정입니다.
